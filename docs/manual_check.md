# 手動での確認事項

自動テストで届かない範囲をまとめたもの。自動化できていない理由も併記する。

自動で確認できる範囲は次の4つで、これらは実行するだけでよい。

```bash
python3 tests/run_tests.py            # Python 実装・ビルド同期・サンプル・組み込みの不変条件
node tests/js_test.mjs                # ブラウザ実装（Node のみ）
python3 tools/diff_impls.py --all     # 2つの実装の挙動差
node tools/browser_check.mjs          # 5つの HTML を実ブラウザで操作（Playwright が必要）
```

---

## 1. 実際の LLM を載せた `ai_*.html`

`tools/browser_check.mjs` は WebLLM を差し替えたスタブで動かしている。スタブは常に書式の整った応答を返すため、**応答が崩れたときの復旧経路を通っていない**。実際のモデルはこの経路に頻繁に入る。

自動化していない理由は、WebGPU 対応ブラウザと 0.8〜2.4GB のモデルのダウンロードが要るため。CI に載せる性質のものではない。

### 手順

1. WebGPU 対応ブラウザ（Chrome / Edge の新しめのもの）で `ai_player.html` を開く
2. 画面上部のセレクタでモデルを選び「▶ ロード開始」
3. ロード完了後、何度か話しかける

### 見るところ

| 対象 | 確認すること |
|---|---|
| `ai_player.html` | `【描写】【心情】【発言】【関係】` が崩れた応答をモデルが返したとき、最大2回の再生成で持ち直すか。持ち直さない場合に既定の応答へ落ちるか |
| `ai_player.html` | 同じ発話が繰り返されたときに `isRepeating` が働いて再生成されるか |
| `ai_player.html` | 応答に外国語が混ざったとき `hasForeignChars` が働くか |
| `ai_branch.html` | 分岐が3つ揃わない応答に対して、最大3回の再試行が働くか。`parseStructuredBranch` が空を返した場合にループが止まらないか |
| `ai_branch.html` | 生成された Yui コードが構文エラーになったとき、そのターンを捨てて次へ進めるか |
| `ai_dialog.html` | 長時間動かしたとき、コンテキスト圧縮が働いてトークン上限に当たらないか |
| 全部 | 「■ 停止」で推論が実際に中断されるか（`interruptGenerate`） |

### 分かっていること

スタブでの検証中、`ai_dialog.html` の応答番号が `12 → 15 → 16` と飛ぶ箇所があった。再試行か並行呼び出しが走っている。スタブでは正常系として処理されるため不具合とは断定できないが、実モデルでは同じ発話の繰り返しとして現れる可能性がある。

## 3. 整数と小数の区別

ブラウザ実装は JavaScript の `Number` を使うため、整数と小数を型として区別しない。これは実装固有の制約で、修正するには数値型のボックス化が要る（SPEC 16 に記載）。

現在残っている2実装の差はすべてこれに起因する。

```bash
python3 tools/diff_impls.py --all
```

組み込み 350 通り中 1 件、演算子 539 通り中 4 件。これ以外の差が出たら、それは新しい不具合。

## 4. 公開リポジトリの履歴

初回コミット `5d90d4e` には実名と所属が含まれており、force push で main からは切り離したが、GitHub は SHA 指定でのアクセスを残す。

消すにはリポジトリの削除と再作成が要る（`delete_repo` スコープ、または Web UI）。実履歴を失う代償に対し、同じ情報が別の公開リポジトリに既に存在することから、現状は据え置きと判断している。方針を変える場合はこの節を書き換えること。
